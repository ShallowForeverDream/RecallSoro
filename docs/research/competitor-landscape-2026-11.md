# RecallSoro 竞品全景调研（2026-11-23 ~ 24）

## 调研范围与方法

- **四路并行子代理**，分别覆盖：GitHub 开源生态、国内商业产品、海外商业产品与 local-first 生态、细分场景（证书归档+证明册）。
- 取证方式：GitHub REST API 逐仓核实 star/许可证/活跃时间、官网/官方文档一手抓取、`bili_watch` 读 B 站字幕与评论区、知乎专栏原文直读。
- 所有数字为 **2026-11-23/24 快照**，标注「未核实」的不作为决策依据。
- 另有一份历史调研 `open-source-research-full.md`（7 路、约 80 个项目，2026-11-22 gh api 核实），本报告与其互补：历史侧重 PKM/台账/时间线/物品，本报告侧重商业产品、local-first 架构与细分场景。

## 一、核心结论（先看这个）

> **市面没有「个人经历总台账」这个品类的成品。** 现有产品都只做其中一段：要么管文件（坚果云/LeafTidy/Eagle/immich），要么管笔记（思源/Obsidian/flomo/Anytype），要么管单一扫描件（夸克/WPS/扫描全能王），要么是机构发证端（Credly/Accredible）。「经历 → 凭证 → 可对外出示的证明册」这条链路没人做通。

三条支撑证据：

1. **需求真实存在**：B站保研材料视频（BV1zTGQ6kEdk）347 条评论，前 15 条几乎全是「求模板」；UP 主只能回复「+小绿标，这里发不了文档」。模板本身成了需要私信索取的稀缺资源。
2. **用户在硬扛**：知乎一手文章记录的现实是——桌面建「保研」大文件夹 → 分子文件夹 → 证书按「奖学金/科研/竞赛/英语/技能」细分 → 每张证书手工重命名为「奖项-时间」→ 四层备份（相册+iCloud+WPS+百度网盘）。
3. **品类词缺失**：B站搜「个人台账」几乎全是财务/工程/行政 Excel 教程；搜「个人数字档案」出来的是数字遗产与档案数字化。用户不知道该搜什么来找这类产品。

**推广启示**：不要用「个人台账」 searched 不到，要用用户已有心智词——「证书整理 / 保研材料 / 获奖证明 PDF / 作品集」。

## 二、功能重叠度警示（哪些是重复造轮子）

GitHub 路线核实出的硬事实：

| RecallSoro 功能 | 已有成熟实现 | 判断 |
|---|---|---|
| 统一收件箱 | paperless-ngx `Tag.is_inbox_tag` | 机制重复 |
| SHA-256 去重 | paperless-ngx（原件+归档双校验）、immich（SHA-1+库作用域唯一约束） | 算法层无新意 |
| 自定义字段 / 表格视图 / 模板 | paperless-ngx SavedView TABLE + CustomField；SiYuan 属性视图+模板片段；Trilium 属性+模板 | 高度重复 |
| 版本回滚 | paperless-ngx `root_document`+`version_index`；Trilium 修订版本；SiYuan history | 机制重复 |
| 本地落盘 + 单目录备份 | Trilium `document.db`、SiYuan workspace、HomeBox SQLite 卷 | 思路重复（Tauri/Dexie 是新组合） |
| OCR | paperless-ngx、immich、SiYuan 内建 Tesseract；Umi-OCR、PaddleOCR 可直接集成 | 高度重复，除非中文证件场景明显更准 |
| 资产台账 + 证件附件 | HomeBox 完整覆盖（图片上传、文档保修跟踪、购买维护） | 重复 |
| 照片/视频 + 手机备份 | immich 完整覆盖 | 若做完整相册则重复 |

**必须承认**：从技术机制看，RecallSoro 的每一个单点都有现成实现。护城河不在技术，在于**把整条链路串成一个开箱即用的领域产品**。

## 三、真正的差异化（查证未见同类）

1. **跨领域经历语义层**：竞赛 + 证件 + 项目 STAR + 游记共用一套数据模型与模板视图——没有任何开源/商业产品把这几类异质人生材料统一建模。
2. **无损脱敏 → PDF 证明册**：把归档延伸到「对外举证」。细分场景调研确认：没有任何工具把「台账 + 带封面目录证明册 + 无损脱敏」合在一起。
3. **局域网点对点传图（无服务器）**：immich/Trilium/HomeBox 都要服务端或同步服务器；我们的 LAN 直传是架构级差异。
4. **纯浏览器存储栈**：Dexie/IndexedDB 作为桌面端主存储，在这 20+ 项目里独一份。
5. **统一收件箱跨类型**：paperless 的 inbox 只针对文档；我们的收件箱同时吃文档、照片、证书、竞赛材料。

## 四、按赛道的产品地图

### A. 国外商业产品

| 产品 | 定位 | 定价（一手） | 与我们的关系 |
|---|---|---|---|
| **DEVONthink** | macOS 文档数据库，扫描 OCR、多版本回滚、自定义元数据 | $99 / $199 / $499 一次性 | 功能最接近（多版本+OCR+本地库），但仅 Apple 生态、闭源 |
| **Eagle** | 设计师素材管理，AI 语义搜索、智能文件夹、MCP | 折后 $34.95 买断，2 设备 | 证明用户愿为本地素材管理付费；但管「素材」不管「经历」 |
| **Anytype** | local-first 对象图数据库，CRDT + SQLite + E2EE + 局域网 P2P | 核心免费，存储超额需会员 | 架构最接近 local-first 理想，但是通用对象库 |
| **Obsidian** | 本地 Markdown + 双链 + 插件生态 | App 免费，Sync $4/月，Publish $8/月 | 教育好了「本地优先」心智，但结构化需插件拼装 |
| **Notion** | 云端块+数据库 | Free / $10 / $20 每人每月 | 国内用户「自建证书台账」的常见土办法，但非本地 |
| **Tana** | ⚠️ 已拆分：笔记产品为 Tana Outliner，tana.inc 现为 AI 会议平台 | 未核实 | 调研时需明确指向 |
| **Capacities** | 对象-块模型，无限对象免费 | Basic 免费 | 自定义对象类型思路可参考 |
| **Paperless-ngx** | 开源自托管文档归档 | 免费 | 功能重叠最高，但服务端范式 |

### B. 国内产品

| 产品 | 定位 | 关键事实 |
|---|---|---|
| **坚果云** | 云同步 + 「收件箱」+ 扫描件自动备份 | 官网原文有一键收集链接、按规则自动重命名——覆盖我们「统一收件箱+扫码传图」一半叙事，但云优先 |
| **LeafTidy 轻羽归档** | 本地离线 AI 文件整理 + 脱敏 + 清 EXIF | 已占住「本地/离线/脱敏」心智；免费；但老 CPU 跑不动、exe 打不开、按区县分类失效（B站评论一手） |
| **思源笔记** | 块级双链 + 数据库视图 + Tesseract OCR + 原生多端 | 本地免费，功能特性买断 ¥80，订阅 ¥148/年；「无离线，不笔记」 |
| **flomo** | 极简卡片速记 | 官方明确「拒绝 All in one」——恰好留出台账空间 |
| **扫描全能王** | 手机扫描→PDF | 自动续费 98 元、免费版水印，评论区大量负面与求破解版——国内用户对订阅+自动续费敏感 |
| **华为/vivo 自带扫描** | 手机原生扫描 | B站高赞「扫描软件天花板是华为自带的」——免费原生能力是真实竞品 |
| **Eagle / Billfish** | 设计素材管理 | 国内用户愿为本地素材管理付费（Eagle 买断制） |

### C. 开源生态（star 为 API 快照）

- **paperless-ngx** 48.5k：文档归档 + inbox tag + 自定义字段 + 表格视图 + 版本链 + OCR
- **immich** 119.9k：自托管照片视频，SHA-1 去重 + 库作用域唯一约束，原生移动端
- **AppFlowy** 79.4k / **AFFiNE** 77.2k：开源 Notion 替代，本地优先 + 数据库视图 + CRDT
- **SiYuan** 47.3k：块编辑器 + 属性视图 + Tesseract OCR + 原生 Android/iOS/鸿蒙
- **TriliumNext** 39.1k：单 SQLite `document.db` + 模板 + 属性继承 + 修订版本
- **Umi-OCR** 48.9k：免费离线 OCR（约一年未更新）
- **PaddleOCR** 93.1k：100+ 语言、结构化输出、印章识别
- **HomeBox** 7.9k：家庭资产台账 + 图片 + 保修跟踪（已覆盖证件类台账）
- **Karakeep** 30.8k：书签一切，AI 打标 + 全文检索
- **reactive-resume / RenderCV / academicpages**：导出闭环的现成零件

⚠️ 已归档不宜依赖：reor、Homebox（旧仓）、Achievement-Watcher；许可标注 NOASSERTION 的需自行确认。

### D. 细分场景：证书归档 + 证明册

- **机构发证端**：Credly（1.23 亿凭证）、Accredible（$45/月起）、闪颁客、轻速云——都是「颁发方」视角，个人只能接收。
- **单一 PDF 工具**：福昕（打码）、Adobe Acrobat Pro（红action 密文）、PDF 批量目录生成器——只做排版，不做台账。
- **通用设计**：Canva（免费 / ¥30/月 / ¥49/月）——逐份设计，无批量无脱敏。
- **证书管理 App**：多为 CA 数字证书（非获奖证书）或企业证照代管，无个人获奖归档产品。
- **OCR 字段抽取**：**没有任何现成工具能从获奖证书图片直接抽出赛事名/奖项/日期**。可行路径是通用 OCR → 文本 → 规则/LLM 抽取。这是可内化的差异化能力。

## 五、local-first 架构参考（手机端/同步的下一步）

| 方案 | 案例 | 对 RecallSoro 的启示 |
|---|---|---|
| **自研 CRDT（AnySync）** | Anytype | 对象建模为 CRDT DAG，多 head 自动合并；本地 SQLite；支持局域网 P2P、完全离线、自托管。官方明确警告 SQLite 不能放云同步目录——我们的 Syncthing 同步是正确做法（同步文件而非直接共享 DB） |
| **通用 CRDT** | Automerge | 完整变更历史 + 分支、压缩列式存储、传输层无关。与版本回滚目标契合，可评估 Tauri 集成成本 |
| **Postgres 同步** | Electric | 已转向 agent 平台并被 Databricks 收编，长期依赖需谨慎 |
| **本地优先参考架构** | Actual Budget | 「Unabashedly local-first」——完全离线、后台同步、自托管、强撤销重做 |
| **Yjs** | 未从一手确认有档案产品采用 | 不列为已落地案例 |

**建议**：附件本体走「内容寻址 + 增量同步」，CRDT 只用于元数据/标签的多端合并，不要整个库上 CRDT。

## 七、战略建议

1. **护城河叙事**：别再主打「本地/离线/隐私」（LeafTidy 已占住且免费），主打「经历→凭证→交付物」的完整链路 + 领域模板 + 证明册。
2. **推广关键词**：证书整理、保研材料、获奖证明 PDF、作品集——不要用「个人台账」（搜不到）。
3. **定价**：倾向买断或一次性付费，避免订阅+自动续费（扫描全能王的负面反馈是前车之鉴）。
4. **功能取舍**：OCR/去重/版本回滚机制已有成熟实现，不必追求自研创新；把精力放在「98 条竞赛级字段 + OCR 字段抽取 + 一键证明册 + 无损脱敏」这条别人没做通的链路。
5. **手机端架构**：参考 Anytype/Actual，附件走内容寻址+增量同步，元数据用 CRDT 或简化的版本向量；SQLite 绝不直接放网盘同步目录。
6. **可抄的零件**：数据模型抄 Open Badges（发行方+图片+断言+校验）；导出接 reactive-resume/RenderCV/academicpages；相册粗分借 PhotoPrism；底座若要服务端可用 NocoDB/SQLPage。
